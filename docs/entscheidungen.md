## 18.11.2026 – Datenbank (Schritt 2)

| Thema                   | Entscheidung                                                                                                                                                                                                                                                                                                                                                                                                | Grund                                                                                  |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| Schreiben nur über RPCs | Clients lesen direkt (unter RLS), Meldungen, Einstufungen, Status, Kommentare und Sperren gehen aber nur über `security definer`-Funktionen (`report_create`, `report_einstufen`, `report_set_status`, `report_comment`, `aircraft_sperren`, `aircraft_entsperren`, `admin_update_user`). Direkt schreiben dürfen Clients nur: eigenen Namen, Fotos zur eigenen neuen Meldung, Flugzeug-Stammdaten (Admin). | Jede Änderung prüft die Rolle und schreibt garantiert den Verlauf.                     |
| Kat-1-Sperrgrund        | Bei Kat 1 ist der `pilotenhinweis` Pflicht und immer sichtbar. Er ist der Sperrgrund, den Piloten sehen.                                                                                                                                                                                                                                                                                                    | Kat 1 setzt keine manuelle Sperre (siehe oben), Piloten brauchen trotzdem einen Grund. |
| Kat 2                   | Ziel ist Pflicht, Pilotenhinweis optional und nur sichtbar, wenn der Wart es so einstellt.                                                                                                                                                                                                                                                                                                                  | Wie im Konzept.                                                                        |
| Kat 3                   | Begründung ist Pflicht und geht als Rückmeldung an den Melder.                                                                                                                                                                                                                                                                                                                                              | Melder soll wissen, warum nichts passiert.                                             |
| Verlauf für Piloten     | Piloten sehen: Sperren/Entsperrungen, alles Nicht-Interne zu eigenen Meldungen, Einstufung und Statuswechsel von Meldungen mit sichtbarem Hinweis (inkl. Kat 1). Keine Kommentare zu fremden Meldungen.                                                                                                                                                                                                     | Rückmeldungen sind für den Melder gedacht, nicht für alle.                             |
| Namen                   | View `profile_names`: Piloten sehen Namen von Warten/Admins und sich selbst, Warte sehen alle. Keine E-Mails.                                                                                                                                                                                                                                                                                               | Entscheidung vom Projektstart, zentral umgesetzt.                                      |
| Admin                   | Ein Admin kann die eigene Rolle/Freigabe nicht ändern.                                                                                                                                                                                                                                                                                                                                                      | Verhindert, dass sich der letzte Admin aussperrt.                                      |
| Ampel als Enum          | `public.ampel` (`gruen`, `gelb`, `rot`).                                                                                                                                                                                                                                                                                                                                                                    | Typsicher im Frontend über die generierten Typen.                                      |
| Hilfsfunktion           | `current_rolle()` statt `current_role()`.                                                                                                                                                                                                                                                                                                                                                                   | `CURRENT_ROLE` ist ein reserviertes SQL-Wort.                                          |
| Fotos                   | Bucket `report-photos` privat, max. 5 MB, JPEG/PNG/WebP. Upload nur in `<report_id>/…` der eigenen Meldung, solange sie `neu` ist. Max. 3 Fotos (Trigger).                                                                                                                                                                                                                                                  | Datensparsam, passt zur Bildkompression im Browser.                                    |

## 18.11.2026 – nach dem ersten lokalen Check

| Thema         | Entscheidung                                                                                                                                                                                 | Grund                                                                                                                                                                                                     |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Hosting       | **Cloudflare Workers mit statischen Assets** statt Cloudflare Pages. Konfiguration in `wrangler.jsonc`, Build über Workers Builds (`npm run build`, `npx wrangler deploy`).                  | Cloudflare legt neue Git-Projekte inzwischen als Worker an. Für eine reine Single-Page-App ist das gleichwertig, `_headers` gilt weiter. Mit `wrangler.jsonc` im Repo ist das Deployment nachvollziehbar. |
| Zeilenenden   | `.gitattributes` mit `eol=lf`                                                                                                                                                                | Unter Windows (`core.autocrlf=true`) meldete Prettier sonst alle Dateien als falsch formatiert.                                                                                                           |
| Branch-Schutz | Gewünscht: `main` nur per PR, CI-Check Pflicht, nur Squash-Merge. GitHub erzwingt Branch-Schutz bei **privaten** Repos erst ab GitHub Pro bzw. Team. Bis dahin gilt die Regel per Absprache. | Kostenloser Tarif. Lösung offen (z. B. GitHub Pro über das Student Developer Pack oder eine Vereins-Organisation).                                                                                        |

| Thema                    | Entscheidung                                                                                                                                                                                                                                                                                         | Grund                                                                                                                                                                                                                               |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Abgrenzung               | EDKN Technik ist eigenständig, kein Modul im SMS-Portal. Technischer Zustand → EDKN Technik, Sicherheitsereignisse → SMS.                                                                                                                                                                            | Klare Zuständigkeit, schlankes Tool. Grenze wird mit dem SMS-Verantwortlichen abgestimmt.                                                                                                                                           |
| Login Prototyp           | E-Mail + Passwort mit Freigabe durch den Admin. Vereinsflieger-Login später (`profiles.vf_uid` schon anlegen).                                                                                                                                                                                       | Sofort startklar, kein App-Key nötig.                                                                                                                                                                                               |
| Sichtbarkeit (vorläufig) | Mittelweg aus `docs/handoff.md` Abschnitt 4. Regeln nur zentral in RLS/Views.                                                                                                                                                                                                                        | Fachlich noch offen zwischen Werkstattleiter und Projektleitung.                                                                                                                                                                    |
| Kat 1 und Sperre         | Eine offene Kat-1-Meldung macht das Flugzeug rot (berechnet in der View). Beim Erledigen eines Kat-1-Punkts bestätigt der Wart ausdrücklich „Flugzeug ist wieder flugklar“, das steht im Verlauf. Die **manuelle Sperre** ist ein eigener Schalter am Flugzeug, z. B. für „Jahresnachprüfung läuft“. | Kein vergessenes Entsperren, aber trotzdem eine bewusste Freigabe.                                                                                                                                                                  |
| Umstufen                 | Ein Wart darf eine Einstufung später ändern (z. B. Kat 2 → Kat 1), mit Eintrag im Verlauf.                                                                                                                                                                                                           | Neue Erkenntnisse in der Werkstatt.                                                                                                                                                                                                 |
| Melder                   | Nach dem Absenden kann der Melder seine Meldung nicht bearbeiten oder löschen, aber einen Nachtrag als Kommentar schreiben.                                                                                                                                                                          | Verlauf bleibt nachvollziehbar.                                                                                                                                                                                                     |
| Namen                    | Piloten sehen die Namen der Warte („gesperrt von …“), aber nicht, wer fremde Meldungen abgegeben hat.                                                                                                                                                                                                | Datensparsam, passt zur Sorge des Werkstattleiters.                                                                                                                                                                                 |
| Doku                     | In `docs/` stehen Rollen statt Namen. Mails und persönliche Daten kommen nicht ins Repo.                                                                                                                                                                                                             | Repo wird mit mehreren Leuten geteilt, evtl. später in eine Vereins-Organisation verschoben.                                                                                                                                        |
| Sprache                  | Fachbegriffe deutsch wie im Handoff (`rolle`, `freigabe`, `kategorie`, `pilotenhinweis` …), technische Namen englisch (`ReportForm`, `useAircraftList`). Commits (Conventional Commits) und Code-Kommentare auf Deutsch.                                                                             | Einheitlich, nah an der Fachsprache.                                                                                                                                                                                                |
| Paketmanager             | npm                                                                                                                                                                                                                                                                                                  | Ist überall vorhanden, keine Extra-Installation.                                                                                                                                                                                    |
| Workflow                 | Jeder Schritt wird committet, gepusht und als PR geprüft. Das Okay der Projektleitung heißt „weiter mit dem nächsten Schritt“.                                                                                                                                                                       | Diff auf GitHub sichtbar.                                                                                                                                                                                                           |
| RLS-Tests                | Laufen zusätzlich in der CI (ab Schritt 2).                                                                                                                                                                                                                                                          | Sicherheitsregeln werden bei jedem PR echt geprüft.                                                                                                                                                                                 |
| Hosting                  | **Cloudflare Pages** statt Vercel (am selben Tag zu Cloudflare Workers geändert, siehe oben).                                                                                                                                                                                                        | Der Vercel-Gratis-Tarif baut bei privaten Repos keine Deployments von Commits anderer Personen (keine Zusammenarbeit im Hobby-Tarif).
